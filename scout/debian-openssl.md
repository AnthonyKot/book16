The six lines wrap two `MD_Update(&m,buf,j)` calls in `/* … */`. One is in `ssleay_rand_add` — the function that is supposed to mix the caller’s seed into the pool. The other is in `ssleay_rand_bytes`, already behind `#ifndef PURIFY` with a 1998 comment `/* purify complains */`. There is no `debian/patches/` in this tree. The changelog bullet is dropped into an unreleased `0.9.8a-9` stanza dated 6 April — four weeks *before* the commit.

- **Why it is a story:** A valgrind ticket (#363516) is a reasonable Tuesday. Nine minutes after importing the generator, the maintainer comments out the line that feeds `/dev/urandom` (and everything else) into the pool, writes “this stop valgrind from giving error messages in unrelated code,” and closes the bug. The moment before the outcome is not malice and not incompetence-as-character: it is a man looking at a Purify workaround that already existed in the same file and extending it one function up, into the seed path, because uninitialized memory “shouldn’t” be entropy. He is doing quality work. The file is at `rand/md_rand.c`. OpenSSL 0.9.8 compiles `crypto/rand/md_rand.c`.
- **What the reader learns:** `Closes: #NNNNNN` is not a review. A six-line comment around a function whose name contains `rand_add` is the whole class of “silencing the sanitizer by removing the read.” `git log -S 'uninitialised' -- '**/md_rand.c'` finds it in one shot.
- **Surprise:** 4 (everyone knows the CVE; almost nobody has seen the nine-minute pair or the wrong path)

`0.9.8b-1` (changelog dated 4 May 2006, tag 14 May) *claims* the valgrind fix and carries the commented file at the unused path. Etch’s `0.9.8c-4` (2006-11-30, `650b59ccf7`) has the comments in `crypto/rand/md_rand.c`. `origin/debian/etch` is an ancestor of both the May overlay and the September move; it is **not** an ancestor of the 2008 fix.

- **Why it is a story:** From May to September the “fix” is a dead file in an overlay VCS. Valgrind is still noisy. On a Sunday afternoon he renames the file onto the path the compiler uses — “really fixing” the ticket — and fifty-seven minutes later has to convert the inner `/* purify complains */` wrap to `#if 0` because nested C comments do not compile. That is the moment the RNG on every Debian box that will become etch stops mixing its seed. The build break is the last chance the compiler had to refuse the leftover half; it never saw the fatal half, which had no inner comment.
- **What the reader learns:** In an overlay/partial-tree packaging repo, a patched file that is not at the upstream path is a no-op, and a later “put it in the right place” commit is the real release. `git log --follow -- '**/md_rand.c'` plus the tag `debian/openssl-0.9.8b-1` is how you watch a CVE stay dark for four months and then go live under a changelog line about a two-year-old bug number.
- **Surprise:** 5

In SSLeay 0.8.1b the `ssleay_rand_bytes` mix of the *output* buffer is already optional, for Purify. `ssleay_rand_add` still always mixes `buf`. Debian 2006 takes the comment as a design rule and applies it to the seed path, which was never behind `PURIFY`.

- **What the reader learns:** `git log -S` on a warning comment finds the ancestor of a CVE. A `#ifndef SANITIZER` that disables a read is a loaded gun; the next person will widen it. Blame the comment, not just the line.
