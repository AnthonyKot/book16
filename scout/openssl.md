The payload-length read and the copy, added in that commit, trust a 16-bit integer from the wire:

```

+/* Read type and payload length first */
+hbtype = *p++;

+pl = p;
```

**Why it is a story.** New Year’s Eve, last minute of the year, a PhD student’s RFC-6520 implementation lands under “Reviewed by: steve” — the same person committing it. There is no unit test. `n2s` pulls an attacker-chosen length; `memcpy` copies that many bytes from the record buffer. For 27 months this is just “heartbeat support.” The moment before the outcome is a quiet Saturday night: a feature, a PR number, a review that is a first name.

**What the reader learns.** A “reviewed by” line that names the committer is not a second pair of eyes. Holiday commits and student patches are where length fields go unchecked. `git log --grep=heartbeat` plus `git show` of the memcpy is how you find the decision, not the CVE writeup.

**surprise:** 3 (everyone knows Heartbleed; fewer have seen 22:59:57 and the four missing lines)

## 2. The fix is a bounds check that would have fit in the original review

- **find-type:** 1 (tiny diff, huge blast radius)
- **hashes:** `96db9023b881d7cd9f379b0c154650d6c108e9a3` (origin, `OpenSSL_1_0_1-stable`); `731f431497f463f3a2a97236fe0187b11c44aead` (cherry-pick on `master`)
- **date:** author 2014-04-06 00:51:06 +0100; committer 2014-04-07 19:44:38 +0100
- **author:** Dr. Stephen Henson `<steve@openssl.org>` (fix prepared by Adam Langley and Bodo Moeller; found by Neel Mehta)
- **message:** `Add heartbeat extension bounds check.` / CVE-2014-0160

```
git -C ~/book16/repos/openssl log -1 --format=fuller --stat 731f431497f463f3a2a97236fe0187b11c44aead
AuthorDate: Sun Apr 6 00:51:06 2014 +0100
CommitDate: Mon Apr 7 19:44:38 2014 +0100
    Add heartbeat extension bounds check.
    A missing bounds check in the handling of the TLS heartbeat extension
    can be used to reveal up to 64k of memory to a connected client or
    server.
 3 files changed, 36 insertions(+), 13 deletions(-)
```

The actual patch in `ssl/t1_lib.c` is four lines of arithmetic:

```
git -C ~/book16/repos/openssl show 96db9023b881d7cd9f379b0c154650d6c108e9a3 -- ssl/t1_lib.c
+/* Read type and payload length first */
+if (1 + 2 + 16 > s->s3->rrec.length)
+return 0; /* silently discard */
+hbtype = *p++;
+n2s(p, payload);
+if (1 + 2 + payload + 16 > s->s3->rrec.length)
+return 0; /* silently discard per RFC 6520 sec. 4 */
```

The first regression test arrives ten days later, from outside the project (`6af080acaf`, Mike Bland, 2014-04-16). Heartbeats are then dismantled in public: TLS path ripped out (`22e3dcb780`, 2016-01), “Remove heartbeats completely” (`6c62f9e163`, 2016-10), reverted two minutes too soon (`b612799a80`, “Done too soon, this is for future OpenSSL 1.2.0”), removed again (`558ea84743`, merged 2019).

**Why it is a story.** The same author-line that shipped the feature ships the fix — but the thanks line names Google and two cryptographers who actually did the work. The bug was “do not copy more than the record holds.” That sentence is also RFC 6520 §4. The moment before disclosure is a 36-line cherry-pick sitting on a Sunday midnight, waiting for Monday’s coordinated release.

**What the reader learns.** After a famous bug, `git log --grep=CVE-2014-0160` shows the patch is small enough to have been the review comment. The test that would have caught it is a later, external commit. Measure “we take security seriously” by when the test appears, not when the advisory does.

**surprise:** 2 (the CVE is famous; the four-line shape of the fix is the receipt)
