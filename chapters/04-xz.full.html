One character

This is the full dig — every command, every receipt. The plain-English telling of the same story is here: One character.

git clone https://github.com/tukaani-project/xz and run shortlog on the years before 2022, and the project is one man:

console$ git shortlog -sn --until=2022-01-01 HEAD
  1259	Lasse Collin
    11	Adrien Nader

This is the compression library that ships in effectively every Linux distribution — in the tools that unpack your kernel, your packages, your container images — and for its entire life it has been Lasse Collin and a long tail of people who sent one patch and left. R10 That is the condition this whole story runs on: an indispensable piece of the world's infrastructure, maintained, essentially alone, by someone doing it for free in his spare time. Keep it in mind, because it is not a weakness anyone was foolish to have. It is the normal state of an enormous amount of the software you depend on.

The welcome

In January 2022 a new contributor sends a patch. It is exactly the kind you want: defensive, small, unglamorous.

console$ git log --all --author='jiat75' --reverse --format='%h %aI | committer=%cn | %s'
6468f7e4 2022-01-28T20:47:55+08:00 | committer=Lasse Collin | liblzma: Add NULL checks to LZMA and LZMA2 properties encoders.

Lasse applies it. R1 Over the next six months "jiat75" sends more — test cleanups, coverage scripts, CMake work — and in August 2022 Lasse writes the name into the file that says who this project belongs to:

console$ git show 692de534fa -- AUTHORS
+    <lasse.collin@tukaani.org> and Jia Tan <jiat0218@gmail.com>.

One line. R2 It is the nicest thing that can happen to a one-maintainer project: someone reliable showed up and stayed. By the end of 2022 Jia Tan is pushing as a committer. By 2023 Jia is doing more of the work than Lasse. Nobody in the room is watching a heist. They are watching a burnout end. That is the point of the two and a half years — not the code, the trust. The backdoor could not have been committed by a stranger. It had to be committed by the co-maintainer, and the way you become the co-maintainer is to be genuinely helpful for a very long time.

The mailing list adds a chorus git cannot show you. Through 2022, unfamiliar names pressed Lasse in public — releases too slow, no progress until there is a new maintainer — and his reply cited long-term mental health issues, an unpaid hobby, and one hopeful development: Jia Tan might take a bigger role. The pressure accounts were never heard from again. Whether they belonged to the same operation, nothing in this repository can prove. What the timeline shows is that they appeared while trust was being built and vanished once it was granted.

A name that only adds one thing

In June 2023 a second name appears, and this one is worth watching because it does exactly one thing and then vanishes:

console$ git log --all --author='Hans Jansen' --format='%h %aI %cn %s'

Hans Jansen exists in this repository from June to October 2023. The work Hans contributes is support for GNU indirect functions — ifunc, the mechanism that lets a library pick which version of a function to use at load time, at runtime. It is a legitimate optimization. It is also the exact hook the eventual payload needs: a place where a resolver runs early and gets to decide what a symbol points to. Hans lands the ifunc groundwork and is never heard from again. R3 I am not going to tell you who Hans was; the git history cannot, and this book only tells you what the git history can prove. What it proves is a name that appears, donates a loading mechanism, and disappears — six months before that mechanism is used.

The weapon that is not here

Now the famous part, and the first surprise is that you cannot git show it. The payload that made CVE-2024-3094 — the code that hooks the SSH daemon's authentication — travelled in a file called build-to-host.m4, a build script. If you go looking for it, you find nothing:

console$ git -C repos/xz log --all --oneline -- m4/build-to-host.m4  # (no output = never tracked)

Empty. The file was never committed. The only trace of it anywhere in this repository is its name, added to a .gitignore nine days before the 5.6.0 release:

console$ git show 4323bc3e0c
    Update m4/.gitignore.
+build-to-host.m4

Read what that does. [R4, R5] Autotools generates the malicious build script into the release tarball. Adding its name to .gitignore means that if a maintainer ever regenerates it locally, git status stays clean and the unexpected file never shows up to be questioned. The crime scene is the tarball, the thing distributions actually download and compile. It is not the repository. Git, the tool everyone trusts to show them what changed, was specifically taught to say nothing. The one-line hygiene commit that taught it is so innocuous that after the breach Lasse himself cherry-picked it forward, twice, because read in isolation it is exactly what it claims to be: tidying a .gitignore.

If you take one habit from this chapter, it is this: diff what you ship against what you commit. They are not the same tree, and the gap is where this lived.

The period

February 2024. Jia adds a build check for Linux Landlock — a kernel sandbox that confines a process, limiting what a compromised binary can reach. Adding sandboxing is precisely what a conscientious maintainer does, and the commit is titled like one: a routine feature test. Here is the C program it compiles to detect whether Landlock is available:

console$ git show 328c52da8a -- CMakeLists.txt
+        #include <sys/prctl.h>
+.
+        void my_sandbox(void)

A lone . on its own line, between the include and the function. R6 It is a syntax error. The test program never compiles, so the check always fails, so CMake decides Landlock is "not available," so xz never sandboxes itself. The Autotools half of the same commit does not have the period. Only CMake.

Someone sat in front of that file and added one character.

It stayed until after the breach was public. When Lasse finally removes it, the entire fix is that same character, deleted, and the message says out loud what the commit was:

console$ git show f9cf4c05ed
    CMake: Fix sabotaged Landlock sandbox check.
    It never enabled it.
console$ git show f9cf4c05ed -- CMakeLists.txt | grep -E '^[+-]'
-.
+

R7 "Sabotaged." A minus, a dot, a plus, a blank line. The word did not exist in this tree until a security researcher named Andres Freund, chasing a half-second of extra latency in SSH logins, found the backdoor and went public on March 29. Everything before that date is written in the language of maintenance. The sabotage and the fix are the same one character, pointing opposite directions.

What it nearly cost

What that period was protecting is the reason this is not a footnote. The payload in build-to-host.m4 rewired the dynamic linker so that, on the machines it targeted, it hooked into sshd — the process that stands at every Linux server's front door and decides who gets in. A backdoored sshd is not a data leak; it is a master key to a large fraction of the internet's servers, shipped through the update channel those servers trust most. Versions 5.6.0 and 5.6.1 were already in the beta branches of major distributions, days from the stable releases that would have carried the key into production everywhere.

It was stopped by an accident. A Microsoft engineer named Andres Freund noticed that his SSH logins were running about half a second slower than they should, went looking for why, and followed the latency into the compression library and out the other side into the backdoor. He posted it publicly on March 29, 2024. The difference between a historical curiosity and the worst supply-chain compromise ever shipped was one careful person being annoyed by half a second.

The exit

Jia's last commits are a tell you can only read backward. Three days before disclosure, at 1:50 in the morning, Jia trims the project's SECURITY.md:

console$ git show -s --format='%h %aI %s' af071ef770
af071ef7 2024-03-26T01:50:02+08:00 Docs: Simplify SECURITY.md.

R8 The lines removed are the ones that would have told a reporter to attach build logs and input files — the exact artifacts that would have described the payload hidden in the test data. It is the last commit Jia both authors and commits. Then the account goes dark.

The final word is Lasse's, returning to a house that turned out not to be his alone. His removal commit reverts the backdoor and reads like an inventory of grief:

console$ git show e93e13c8b3
Remove the backdoor found in 5.6.0 and 5.6.1 (CVE-2024-3094).
...
  - The maintainer who added the backdoor has disappeared.
  - Backdoors are bad for security.
This reverts the following without making any other changes:

R9 He lists the reverted commits like a table of contents for the attack, and then he edits AUTHORS the way you edit a headstone: the second name comes out of the header and reappears lower down, labelled, dated, sealed off. The years 2022 to 2024 become a marked interval. The project is one person's again.

What to read twice

The uncomfortable lesson of xz is that none of the usual defenses were asleep. The code was reviewed. The maintainer was diligent. The contributor was, by every visible signal, excellent — for years, because being excellent for years was the attack. You cannot grep your way to catching this; the malicious commits are, one at a time, indistinguishable from good ones, and the two that matter most are a .gitignore tidy and a whitespace-shaped ..

But two habits would have narrowed it, and they cost nothing. First: your release tarball is not your git tree — git archive a tag, diff it against what you actually publish, and look hard at anything in the shipped artifact that is not in the repository, especially generated build scripts. Second: read the negative path of every "improvement." A commit that adds a sandbox check is a commit that can also quietly disable one, and the difference can be a single character that git log --grep will never find because the message says the opposite of what the diff does. Blame, here, is not a question of who to punish. It is a question of which line to read twice.
