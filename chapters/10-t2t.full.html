Giving 0 losses

This is the full dig — every command, every receipt. The plain-English telling of the same story is here: Giving 0 losses.

console$ git -C repos/tensor2tensor log --reverse --format='%h %ai %an %s' | head -2
cedf0e2d 2017-06-15 11:24:53 -0700 Ryan Sepassi first commit
3d9c62f2 2017-06-15 11:27:28 -0700 Ryan Sepassi initial push

The first commit is one line, a README that says # tensor2tensor. The second commit, 155 seconds later, is 74 files and 15,315 lines — and one of those files is models/transformer.py, whole, working, already able to train English–German translation. R1 Its docstring does not say "Attention Is All You Need." It says:

console$ git -C repos/tensor2tensor show 3d9c62f2ac:tensor2tensor/models/transformer.py | sed -n '15,18p'
"""transformer (attention).

encoder: [Self-Attention, Feed-forward] x n
decoder: [Self-Attention, Source-Target-Attention, Feed-forward] x n

R2 Two lines of architecture that would eat the next decade, described with the enthusiasm of a parts list. The paper had gone to arXiv three days earlier.

This repository is where its code came out to live, and the birth is not a birth — it is a delivery. The name on both commits is Ryan Sepassi, the engineer with permission to push, and the AUTHORS file in the push names exactly one author: Google Inc. R2 I went looking for the paper's people. Some arrive in the following weeks and stay for years; three of the eight never touch this history at all:

console$ git -C repos/tensor2tensor log --author='Uszkoreit' --oneline | wc -l
0

R3 Same for Polosukhin, same for Llion Jones. The architecture arrived in public git as a fait accompli: a company named as author, an engineer doing the push, the inventors appearing later, if at all. The history I wanted had happened somewhere else, in a repository I could never clone.

The projection

This git says so on almost every commit, if you read the trailers: PiperOrigin-RevId: 159726434. Piper is Google's internal monorepo; every interesting commit here is an export from it, stamped with the internal revision it mirrors. What you are reading is a projection of a workshop onto a public wall — and in week one, the projector showed too much:

console$ git -C repos/tensor2tensor show 01787ca8a5 | grep -E '^[+-]' | grep -iE 'blaze|brain' | head -2
-./blaze-bin/third_party/py/tensor2tensor/data_generators/replace_oov \
-      (see learning/brain/google/python/ops/candidate_sampling.py)

R4 For six days the public tree carried Google's internal build paths and a pointer into learning/brain/google. The cleanup commit's subject is disarmingly frank — Add leakr dictionary to prevent internal stuff leaking out — and its public diff is two deletions, because the dictionary itself, the list of things that must not leak, stayed inside. R4 By day six they knew: the projection shows the office.

look_right

The dig at the center of this repository needs one piece of background. A model like this learns by predicting the next word of a sentence it is already holding. During training the full sentence is in memory, so the code must blindfold each position — a mask — to keep it from reading the words it is supposed to be predicting. The mask is the exam conditions. Take it away, and the exam is open-book, and the model doesn't learn language; it learns to copy.

Six weeks after launch, on the first of August, a commit arrives whose subject is about translation data — More WMT corrections, port image problems to Problem. R5 Folded into it, among the day's ported chore-work, the local masked-attention function gets a new signature:

console$ git -C repos/tensor2tensor show 75270907db -- tensor2tensor/models/common_attention.py | grep -B1 -A2 'masked_local_attention_1d'
-def masked_local_attention_1d(
-    q, k, v, block_length=128, name=None):
-  """Attention to the source position and a neigborhood to the left of it.
+def masked_local_attention_1d(q, k, v,
+                              block_length=128, look_right=True,
+                              use_whole_block=False, name=None):

R6 Read the old docstring against the new default. The name promises a mask. The old documentation promised a neighborhood to the left — the past only. The new version can also look right, and looking right is on by default. There are honest reasons to want the option — an encoder, reading a finished sentence, may look wherever it likes — and this is exactly the kind of commit I skim in my own review queue: a bulk port, subject about something else, forty files of Tuesday. The next day the whole file moved from models/ to layers/ in a housekeeping commit R7, so by the end of the week even the address on the change was new.

Now train something on that code path, because this is the part worth sitting in. Your model's loss — the running measure of how wrong it still is — starts to fall. It keeps falling. It falls past where your last run flattened out, past what the paper reports, and it is still going, and for a while this is simply the best training run you have ever watched. Everything you know says a lower loss is a better model. You start composing the message to the team. Somewhere in there — an hour in, a day in, depending on how much you wanted it — a different feeling arrives, the one that took me years to install: this is more improvement than the change I made can explain.

In a model that predicts the future, a perfect score is not mastery. It is a leak.

On August 4, the person who reads the curve correctly is the first author of the paper:

console$ git -C repos/tensor2tensor show -s --format=fuller a0bd0177bf | head -8
Author:     Ashish Vaswani <avaswani@google.com>
AuthorDate: Fri Aug 4 14:41:57 2017 -0700

    Reverted back to the previous masked_local_attention_1d because the current
    one was giving 0 losses indicating that it was peeking into the future.

R8 Giving 0 losses indicating that it was peeking into the future. A blindfold with an opt-out, opted out — and the man who knew what the blindfold was for read a perfect score as the proof it was off. Sixty-nine hours after the default landed, his revert deletes the parameter, restores the left-only neighborhood, and writes the diagnosis into the commit message, where the next person staring at a miraculous curve on this code will find it. No postmortem, no incident channel the public can read. Just the sentence, left where it would be needed.

This breaks existing models

June 30, 2017 — the library is sixteen days old. Shazeer finds the subword tokenizer isn't invertible: text in, tokens, text out, and you don't always get your text back. His fix does not hide its cost:

console$ git -C repos/tensor2tensor show -s --format=fuller 98be812807 | head -7
Author:     Noam Shazeer <noam@google.com>

    Fix subword_text_tokenizer to make it invertible again.   This breaks
    existing models and vocabularies.

R9 This breaks existing models and vocabularies — in the subject line, undisguised. Every model anyone had trained in the library's first two weeks became a museum piece that Friday. Correctness won, and it was the obvious call, because the world's investment was sixteen days deep.

Two and a half years later, an outside contributor sends the kind of fix I would like to think I'd have sent. Reading the positional-encoding code — the formula that tells a Transformer where each word sits in the sentence — they notice the count starts at zero, and propose the tidier arithmetic:

console$ git -C repos/tensor2tensor show e3e54900d3 -- tensor2tensor/layers/common_attention.py | grep -E '^[+-].*position'
-  position = tf.to_float(tf.range(length) + start_index)
+  position = tf.to_float(tf.range(1, 1+length) + start_index)

R10 Count from one instead of zero. One line. Nothing about it looks dangerous: no file format changes, nothing fails to load, every test that ran before runs after. It is merged on December 12, 2019, and sits on HEAD for nine days — nine days in which the change is, by every visible measure, fine. Then:

console$ git -C repos/tensor2tensor show -s --format=fuller e4ea462e73 | head -9
Author:     T2T Team <no-reply@google.com>
Commit:     Copybara-Service <copybara-worker@google.com>

    *** Reason for rollback ***

    This change will break existing checkpoints in a hard to debug, hard to
    notice manner. Existing checkpoints will still load and run, but produce
    entirely incorrect results.

R11 By the end of 2019 the world was two years deep in trained Transformers, and every one of them had learned, in its millions of weights, to expect the position signal exactly where the old counting put it. Shift the numbering and nothing crashes — the checkpoints still load and run — they just quietly stop meaning anything. So the same project that broke every vocabulary at sixteen days refused a one-line correction at two and a half years. Nothing in the code had changed sides. The installed base had.

The spec is not the paper. The spec is the weights people have already trained, and the weights have shipped.

At home

Since this dig I pickaxe the guards. git log -S on the names of your safety mechanisms — mask, causal, look_right, whatever enforces your invariants — because the commit that loosens a guard is almost never about the guard; it rides inside the day's chore-work, and pickaxe is how you find it. Read commit subjects for breaks existing and Reason for rollback while you're there — in research code those are the real changelog. And the next time one of your own metrics improves more than your change can explain, don't compose the good-news message yet. Ask what the code can suddenly see.
