How to check this book

Every claim in every chapter is a real object in a public git repository. Nothing is paraphrased from memory. Each chapter ends with a receipts list: for every finding, the exact command that produced it. The prose only quotes output that a command actually printed.

Reproduce a dig yourself

Clone the repository the chapter names, then run the commands from the receipts. For chapter 01:

console$ git clone https://salsa.debian.org/debian/openssl.git
$ git -C openssl show 8f27a7dc02   # the nine-minute commit

The hashes are stable. If a command in this book does not print what the chapter says it prints, that is a bug in the book, and the git history is the authority — not the prose.

The find types

Each dig is one of a small set of shapes: a tiny diff with a huge blast radius; a planted or faked date; what day one really shows; a name that appears or disappears; a comment that outlived its code; a rule enforced by reverts; a feature that became the vulnerability; a diff that rolls back reality; an empty commit; a signature that answers a question nobody asked.

Blame — git archaeology. Every hash is real; clone the repo and run the command.
